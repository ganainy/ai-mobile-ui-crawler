# Issue #20: CLI `stats RUN_ID`

## What
The GUI's Run History "View Stats" dialog (persisted `run_stats` record) had no CLI equivalent. `mobile-crawler stats RUN_ID [--format table|json]` now prints it.

## Changes
- New Qt-free `core/run_stats_sections.py`: `RUN_STATS_SECTIONS` (section titles, labels, `RuntimeStats` attributes) and `format_stat_value` moved out of `ui/widgets/run_history_view.py`, so the GUI dialog and the CLI show the same sections and formatting. `format_stat_value` gained a `missing` placeholder argument (GUI keeps the em dash; the CLI uses `-` because the em dash garbled when piped on Windows). `persisted_stats_dict` returns only the columns `RuntimeStats.to_db_dict` stores, with `_json` columns decoded, so live-only fields don't appear as misleading zeros.
- `cli/commands/stats.py`: table by default (sections as in the GUI plus a CLI-only "Phases" section), `--format json` is a flat dict of persisted fields plus `run_id`, `app_package`, `status` and a `phases` object. Phase data comes from `StepPhaseRepository.get_run_phase_stats` (the `step_phase_transitions` table): transitions, full cycles (checkpoint->capture), average step span. Errors to stderr with non-zero exit: invalid id, unknown run, run with no stats row.
- `RunStatsRepository.get_run_stats` now joins `runs` for `app_package` (`RuntimeStats.from_db_dict` reads it). run_stats never stored it, so the GUI dialog's "App Package" row was always "—"; it's now filled in the GUI too.
- No `-n/--limit`: it's a single-run command.

## Not done
- The issue's problem list also mentions screens/min, tool calls/step and a11y/OmniParser timings: these are live-only (not in `to_db_dict`, no columns anywhere), so they can't be shown without a schema change. Success rate isn't a row either (GUI doesn't show it; it's `successful_steps/total_steps`).

## Review
Two-axis /code-review. Acted on: GUI/CLI mismatch from the CLI backfilling `app_package` onto the stats object (moved into the repository), weak `"12" in out` assertion, no guard against a typo'd section attribute (test added), phase transitions are persisted after all (added). Left: sibling commands' slightly different try/except layout; JSON includes persisted fields the table doesn't (screen size, video, invalid bbox).

## Verification
- `tests/cli/test_stats_command.py` against a real temp SQLite DB; full suite green. Not run against the user's real `crawler.db`.
