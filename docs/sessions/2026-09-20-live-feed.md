# Live Feed: device screen streamed into the Stats panel

Grilled the design first (Live Feed term added to `CONTEXT.md`, [ADR 0004](../adr/0004-drive-vendored-scrcpy-server-directly.md)).

**Changes**
- `domain/scrcpy_stream.py`: pushes the vendored scrcpy 3.3.4 server jar with the project adb (`adb -s <serial>`, so wireless serials work), `adb forward`, raw H.264 over the socket, PyAV decode to RGB. 720 px / 15 fps, video only, no control.
- `ui/live_feed_worker.py`: `QThread` emitting `QImage` frames; every failure ends in a `failed` signal, never an exception into the crawl.
- `ui/widgets/stats_dashboard.py`: the "Screenshot" board is now "Device": a `Live` checkbox, a stacked static screenshot / `_LiveFeedView`, and a Restart button after a failure. Parsed-element boxes are painted over the live frames and fade out over 3 s (`OVERLAY_FADE_SECONDS`); bounds are absolute device pixels scaled by frame width / device width (`wm size`). When the feed is off or dead the board shows the last screenshot with the old PIL overlay.
- `ui/main_window.py`: feed starts at crawl start on the selected device, restarts on device change, stops on crawl end/error/close.
- `av` added to `pyproject.toml` and installed into `.venv312` (user approved); jar under `src/mobile_crawler/resources/scrcpy/`.

**Verified:** tested against the user's phone over wireless adb: first frame in ~1.3 s, 720x328 frames into the dashboard, adb forward removed on stop. Found and fixed a non-contiguous ndarray bug this way. Unit tests: `tests/domain/test_scrcpy_stream.py`, `TestLiveFeed` in `tests/ui/test_stats_dashboard.py`. Not yet run inside a full crawl; fade overlay alignment not eyeballed.

**Follow-up (size):** the Device column now fills the panel height (max width 420 -> 640, no bottom stretch, live view Expanding); frame keeps the phone aspect ratio via KeepAspectRatio. Offscreen check at 850x1050: view 405x966.
