# A11y statistics and INFO timing log

Agreed via grilling (all recommended answers):
- Measures the Portal fetch (`driver.get_ui_tree()`), the existing `breakdown["a11y"]`.
- Recorded in every parser mode; Stats panel shows "Avg A11y: N ms" and "A11y used: X/Y steps" (used = `omni_source == "a11y"`).
- One new INFO line per capture: `a11y fetch took Nms (nodes=N, used=yes|no[, error=...])`; "State capture" line unchanged.
- Not persisted: OmniParser time isn't either, so the run report is unchanged.

Follow-up (user pasted the GUI INFO log): run 178's `crawler_trace.jsonl` had `a11y fetch took...`, `State capture...`, `Step N/M`, `Manager response` etc., but the viewer showed almost none of the `crawler_agent` logger's INFO records (only "Running CrawlerAgent" and one "Execution complete"). Read the whole path (CrawlerLogHandler -> on_debug_log -> SignalAdapter -> _on_debug_log -> LogCleaner -> LogViewer): no filter found, LogCleaner passes these lines when tested directly; cause unknown. Fix: the per-step INFO line is now one `State capture ... | a11y <ok|empty|failed (err)> Nms (nodes=, used=) | omniparser <skipped|ok Nms|empty|failed (err)> | phase=ms...` emitted on the provider's `mobile_crawler.*` module logger (the same route as the service's "Step N: tool=..." lines, which do show), plus a DEBUG copy on `crawler_agent` for the trace. Replaces the separate `a11y fetch took` line. Tests in `tests/domain/test_droidrun_target_package_guards.py`. Not seen in the GUI.

Path (mirrors OmniParser): `provider.py` sets `ui_state.a11y_ms/a11y_used` -> manager/stateless-manager/fast-agent copy to `SharedState` and their response events -> `crawler_agent_service` emits `on_a11y_timing` -> `SignalAdapter.a11y_timing` -> `CrawlStatistics` -> `StatsDashboard`.

Executor events don't carry it (same as OmniParser). In `omniparser` mode "used" is always 0/Y.

Tests: `TestA11yStats` in `tests/ui/test_stats_dashboard.py`; fake signal adapter in `tests/ui/test_main_window.py` gained `a11y_timing`. Not run on a device.
