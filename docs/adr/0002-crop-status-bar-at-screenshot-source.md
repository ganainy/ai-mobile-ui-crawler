# Crop Status Bar Exclusion at the screenshot source

Status Bar Exclusion needs to reach hashing (screen_hash.py), OCR grounding, OmniParser, and AI vision — cropping each consumer separately would mean four call sites re-implementing the same crop. We instead crop once, in `driver.screenshot()`, so every consumer downstream receives an already-cropped image. The trade-off: the live stats-dashboard preview and archived trajectory screenshots also lose the excluded band, since they read from the same source. It also means coordinates derived from the cropped image (OmniParser's ratio bboxes, OCR grounding's pixel bboxes) need the crop height added back before they're used as absolute device tap coordinates — accessibility-tree bounds are unaffected since `get_ui_tree()` is a separate call already in absolute device coordinates. Cropping per-consumer instead would have preserved the full screenshot for display/archival and avoided the offset math, at the cost of duplicating the crop logic across four places and risking them drifting out of sync.
